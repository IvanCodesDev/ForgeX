# 数据集

## `print_farm_400.csv` — 虚拟机群物理仿真数据（400 单 / 8 台机）

**这不是真实产线数据**，但它与「合成数据」有本质区别，值得说清楚。

### 它是怎么来的

由 [`tools/farm-sim.js`](../tools/farm-sim.js) 生成：

```bash
node tools/farm-sim.js --machines 8 --jobs 400 --seed 20260726 \
  --out datasets/print_farm_400.csv \
  --json datasets/print_farm_400_telemetry.json
```

8 台虚拟机器，每台有一组**确定性的固有物理特征**（由机台编号派生，同编号永远相同）：

| 机台       | 机型    | 积碳     | 咬合     | 料阻 | 加热     | 温度上限 | 环境   | 风扰     | 腔体 |
| ---------- | ------- | -------- | -------- | ---- | -------- | -------- | ------ | -------- | ---- |
| FX-256-01  | CoreXY  | 0.09     | **0.74** | 0.67 | 0.94     | 283°C    | 35.1°C | 0.02     | 封闭 |
| FX-256-02  | CoreXY  | 0.01     | 0.82     | 0.01 | 0.97     | 292°C    | 37.5°C | 0.07     | 封闭 |
| FX-256-03  | CoreXY  | 0.55     | 0.97     | 0.89 | 0.84     | 258°C    | 32.0°C | 0.23     | 封闭 |
| FX-256-04  | CoreXY  | 0.00     | 0.78     | 0.69 | **0.80** | 248°C    | 36.4°C | 0.17     | 封闭 |
| FX-220-01  | i3 龙门 | 0.85     | 0.95     | 0.67 | 0.92     | 278°C    | 24.0°C | **0.64** | 开放 |
| FX-220-02  | i3 龙门 | **0.87** | 0.80     | 0.55 | 0.99     | 297°C    | 25.5°C | 0.45     | 开放 |
| FX-Δ260-01 | Delta   | 0.47     | 1.00     | 0.53 | 0.89     | 269°C    | 22.7°C | 0.49     | 开放 |
| FX-500-01  | 大幅面  | 0.33     | 1.00     | 0.07 | 0.99     | 296°C    | 36.0°C | 0.14     | 封闭 |

仿真按这些特征真实演化，故障是因果链的结果：

- 热端积碳 × 温度不足 × 体积流量过大 → 挤出负载超限 → **堵料**
- 送料咬合力不足 × 料架阻力 × 料盘将空 → 打滑 → **断料**
- 加热器有效功率不足 → 够不到高温材料目标 → **热失控 / 加热失败**
- 床温低于材料下限 × 环境冷有风 × 材料收缩率 × 大平面 → **翘边**（完成时判废）
- 需支撑却未开启，或冷却/层高/速度不足 → **悬垂塌陷**（完成时判废）

**随机只用于排产**（这一单派给哪台机、用什么材料和参数）——那是真实产线本来就有的
订单多样性。成败与故障类型完全由物理决定，**没有任何 `pFail` 概率抽样**。

### 与旧合成数据的区别

|                             | 旧合成数据                                                          | 虚拟机群             |
| --------------------------- | ------------------------------------------------------------------- | -------------------- |
| 故障怎么来的                | `machineFailBase = { "FX-256-03": 0.2 }` 写死，然后 `rnd() < pFail` | 物理量越过报警阈值   |
| 「03 号机故障率高」这个结论 | 是生成参数的回显，毫无信息量                                        | 是算出来的，可被证伪 |
| 改工艺参数                  | 故障分布不变（与参数无关）                                          | 故障分布跟着变       |
| 交互效应                    | 只有写死的那一条                                                    | 自然涌现             |
| 分析引擎的价值              | 把常量读回来                                                        | 真的在做归因         |

### 数据里有什么值得分析的

这些结构**没有一条是硬编码的**，全是物理演化的结果：

- **FX-256-04 × ABS = 72.7% 失败，全部是热失控** — 那台机加热器有效功率 0.80，
  稳态上限 248°C，够不到 ABS 需要的 255°C。
- **FX-256-01 × TPU = 66.7% 失败，全部是断料** — 那台机咬合力 0.74（全机群最弱），
  而 TPU 需要的抽送力最大。
- **FX-220-01 × ABS = 80% 失败，全部是翘边** — 开放机型，24°C 室温，风扰 0.64，
  再叠加 ABS 的高收缩率。
- **一个反直觉的点**：FX-256-01 的热端是全机群第二干净的（积碳 0.09），
  却是总失败率最高的机器（30.6%）——因为它的短板在送料侧，不在热端。
  简单按「故障率排序」会误导维护决策，必须看故障类型分布才知道该修什么。
  这正是数据分析该发挥作用的地方。

### 复现

```bash
node tools/farm-sim.js --machines 8 --jobs 400 --seed 20260726
```

同 seed 逐行完全一致。改 seed 会得到不同的排产，但**机台特征不变**
（特征由机台编号决定，不由 seed 决定），所以各机台的强弱关系稳定——
就像真实设备一样。

## `print_farm_400_telemetry.json` — 配套遥测

每单的物理证据，CSV 里放不下的部分：

```jsonc
{
  "job_id": "FARM-0008",
  "machine_id": "FX-Δ260-01",
  "raw_fault": "喷嘴堵塞预警",
  "clog_load_max": 1.06, // 挤出负载峰值，>1 即越线 ← 这一单是它越线了
  "slip_risk_max": 0.49, // 送料打滑峰值，未越线 → 确实不是断料
  "warp_risk": null, // 中途故障，没走到判废评估
  "overhang_risk": null,
  "temp_dev_max_c": 4.2,
  "nozzle_temp_c": 219, // 操作员把温度调低了 → 触发因素
}
```

**故障类型与越线的机制必须对得上**，这一点有测试断言
（`tests/farm.test.js` §7）。

## 用你自己的数据

上面这些都是仿真数据。要分析真实生产：

1. 「洞察」面板 →「上传 CSV」，中英文表头宽松匹配（见 `HEADER_ALIAS`）；
2. 或用本机仿真器跑几单，「本机采集」数据集会记录真实的物理仿真结果。

字段口径见 [`doc/architecture.md`](../doc/architecture.md) §4.4。
