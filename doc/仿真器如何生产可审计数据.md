# 我们如何让 3D 打印仿真器生产可审计数据

> How FORGE·X turns FDM simulation, real G-code replay, and machine logs into traceable manufacturing evidence.

很多 3D 打印演示的问题不在视觉，而在证据链：动画很像真的，数据却来自另一套脚本；
仪表盘能讲故事，但故事早已写进随机数概率；导入文件以后只显示文件名，没有任何可验证的
路径或统计关系。

FORGE·X 的 P2–P5 重构围绕一个问题展开：**一条结论能不能沿着数据链反向追到路径、物理量、
来源和计算方法？**

## 1. 先让动画与计算共享一份路径

自产模型由切片器生成 `layers → paths → points`。打印动画、2D 层预览、3D 路径预览、
耗材估算和 G-code 导出都消费同一个结构。这样修改周界、填充或支撑时，不会出现
“界面画的是 A、导出文件却是 B”。

P5 把真实 G-code 也归一成同一结构。解析器处理常见 Cura/PrusaSlicer 类型注释、
绝对/相对坐标和挤出模式，并在每条路径保留真实 `filamentMm`。导入任务不需要另一套
演示播放器，直接复用现有的层预览、3D 沉积和打印状态机。

这不是完整固件模拟。当前圆弧按端点直线近似，固件宏、压力提前、输入整形和真实加速度
不会被假装实现；遇到这些边界，界面给出警告。

## 2. 把“计划”拆成两种口径

一份切片器 G-code 通常同时包含两类信息：

- 运动与挤出命令，可以重新计算路径长度、E 增量和匀速运动时间；
- 切片器在注释里声明的时间与耗材估算。

FORGE·X 不选择其中一个当“标准答案”，而是并列展示 `claimed` 与 `computed`，保留相对差和
口径说明。时间差可能来自加速度、预热、换层和固件宏；耗材差通常应更小，因为两侧都能追到
E 值，但材料密度和回抽口径仍会影响克重。

## 3. 真机日志让计划遇到实测

P5 增加 `forgex-machine-log` v1 JSON 契约，也接受带常见列名的 CSV 遥测。日志可以提供：

- 实际任务时长；
- 耗材长度或克重；
- 完成层数与任务状态；
- 喷嘴和热床温度样本。

对比层保留 `planned`、`actual`、相对差、容差与解释。这里的目标不是自动宣布某侧错误，
而是快速发现值得继续排查的偏差：中途暂停、机台加速度配置、传感器口径、材料密度，或任务
未完成。

## 4. Profile 是数据扩展，不是代码插件

传统“插件化”很容易把社区 JSON 变成代码执行入口。FORGE·X 选择更窄的边界：

- machine profile 只能选择已经实现的 CoreXY、i3、Delta 或 gantry 运动学基座；
- material profile 只能声明温度、密度、流量、速度、风扇、收缩与参考价格；
- schema 和运行时使用同一组范围，未知字段与越界值直接拒绝；
- 社区 ID 不能覆盖内置 Profile；
- `source` 必填，示例值明确标为示例，不包装成制造商建议。

社区机型会影响构建空间、坐标换算、调平范围和物理特征，但 3D 外观仍复用运动学基座。
这是一个有意保留的真实性边界：没有目标设备 CAD，就不声称视觉模型一比一。

## 5. 数据集需要 manifest，而不只是一个 CSV

一个 CSV 文件无法回答“它从哪里来、能不能复现、有没有个人信息、是否被改过”。P5 为
社区数据集增加 manifest：

- `provenance` 明确区分脱敏真实数据、物理仿真和合成数据；
- `license` 与 `privacy` 说明能否分发、是否包含个人数据和匿名化边界；
- `source` 保存生成器、命令与 seed；
- 每个文件记录 SHA-256；
- 表格记录预期表头和行数。

`node tools/validate-ecosystem.js` 会在主测试链中核验这些约束。哈希只能证明文件与声明一致，
不能单独证明内容来自真实产线；真实度仍需要可审计的采集流程和贡献者责任链。

## 6. 让证据链成为测试对象

P5 新增的测试不只检查“函数返回了东西”，而是检查跨模块不变量：

- G-code 导出再导入后，层数、路径长度、耗材与体积守恒；
- 每条导入路径保留真实 E 增量，打印回放按该增量记账；
- Delta 中心原点不会再被重复平移；
- 危险 Profile、未知运动学、代码字段和内置覆盖被拒绝；
- 真机日志的计划/实测两侧原值和解释都被保留；
- 数据集文件哈希、表头与行数和 manifest 一致；
- 浏览器端真实走通 G-code → 3D 路径 → 真机日志，以及 Profile → 新机型/材料。

## 结语

“仿真数据”不等于“随便编的数据”。只要物理状态、输入参数、随机种子、来源声明和计算口径
都能追溯，它就可以成为可复现的数字实验；只要边界被清楚标注，它也能和真实日志一起用于
工艺排查。

FORGE·X 的核心亮点不是把仿真包装得像真机，而是让每个画面、数字和结论都能回答：
**它从哪来，怎么算的，哪里仍然不知道。**
